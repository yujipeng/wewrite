# 贴图创作手册

贴图（图片消息）的读者在信息流里先看到首图，再决定是否左滑。创作顺序应当反过来：
先想清楚“读者为什么要滑到第二张”，再决定拍什么、写什么。

## 1. 选题判断

适合贴图的题材：

- 一组可并置的画面：探店、旅行、穿搭、改造前后、产品细节；
- 步骤/清单：教程步骤、清单盘点、对比选择；
- 现场记录：活动、展览、发布会，文字只做旁白；
- 观点配图：一张图一个判断，文字负责解释。

不适合贴图、应走长文流程的题材：

- 需要长论证、引用数据、代码或表格；
- 只有一张封面图、正文很长的常规文章；
- 需要排版组件（时间线、引用卡、步骤卡）的内容。

## 2. 图片叙事

写 `image-plan.md` 时逐张回答四个问题：

1. 这张图让读者看到什么新信息？
2. 它和上一张是什么关系（递进、对比、补充、转折）？
3. 没有文字说明时，读者能否看懂？
4. 如果只能保留三张，它是否值得保留？

常见节奏：

- **封面 → 全景 → 细节 → 细节 → 收束**：探店、旅行；
- **问题 → 过程 → 结果**：改造、教程；
- **A → B 对比**：选择、测评；
- **一句判断 + 一张证据图**：观点类。

图片数量建议 3–9 张。超过 12 张时检查是否有重复信息。

## 3. 文案

- 标题：≤32 字；写具体对象和结果，不写“震惊”“必看”。
- 正文：200–800 字；短段落；可以用换行制造节奏。
- 每段只承担一个信息，避免在贴图里写长论证。
- 不使用 HTML；外链会被过滤，需要引导时写账号名或关键词。
- 图片说明写进 `image-post.yaml` 的 `caption`，发布前逐张核对。

## 4. 图片硬性要求

| 项目 | 要求 |
|---|---|
| 数量 | 1–20 张，首图为封面 |
| 格式 | jpg / jpeg / png / bmp / gif |
| 单张大小 | ≤10MB |
| 推荐比例 | 3:4（0.75） |
| 封面裁切 | 支持 1:1、16:9、2.35:1 |

比例偏离 3:4 不会导致失败，但可能在信息流里被裁切。首图务必保证主体居中，
并在 1:1 裁切下仍然完整。

## 5. 发布前检查

```bash
wewrite image-post-check --post <run_dir>/image-post.yaml --json
```

逐项确认：

- [ ] 标题 ≤32 字，没有夸张承诺；
- [ ] 正文为纯文本，没有 HTML/外链；
- [ ] 图片 1–20 张，全部可打开；
- [ ] 首图适合做封面，1:1 裁切主体完整；
- [ ] 图片顺序与文案节奏一致；
- [ ] 事实、数字、地点可核对；
- [ ] 没有虚构亲历和侵权素材；
- [ ] 用户已明确授权推草稿箱。
